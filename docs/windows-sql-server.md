# Windows desktop build with local SQL Server

The till runs as an Electron app that keeps its own Microsoft SQL Server
database on the Windows machine. Sales are committed locally first, and a
background worker syncs with the cloud when a connection is available.

## Layout

```text
electron/
  main.cjs          windows, IPC registration, backup dialog
  preload.cjs       contextBridge -> window.pos
  db/pool.cjs       mssql connection pool + schema bootstrap
  db/schema.sql     local tables with the sync block
  db/repo.cjs       operation -> parameterised T-SQL
  sync/worker.cjs   push/pull routines
```

## One-time setup

1. Install SQL Server Express and enable TCP/IP for the instance.
2. Create an empty database (default name `LovablePOS`). Tables are created
   automatically on first connect.
3. Install the shell dependencies:

   ```bash
   npm install --save-dev electron @electron/packager
   npm install mssql
   # Windows integrated auth also needs:
   npm install msnodesqlv8
   ```

4. Nothing else to wire up: `package.json` already declares
   `"main": "electron/main.cjs"`, and the desktop build sets `base: './'`
   automatically (see `docs/run-locally.md`).

## Running and packaging

```bash
npm run desktop:dev      # against a running `npm run dev`
npm run desktop:build    # run the production build in the shell
npm run desktop:package  # release/LovablePOS-win32-x64/
```

Cloud credentials come from `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` in the
main process environment.

## Sync rules

- **Push** - rows with `is_synced = 0` are read in dependency order (parents
  before children), batch-upserted on `id`, then marked `synced`. A row that
  fails five times becomes `quarantined` and is listed in Settings so it can be
  retried deliberately.
- **Pull** - catalogue tables only (products, tiers, promotions, settings),
  applied with `MERGE`. Sales, shifts and bookings are never pulled, so a cloud
  read can never overwrite work done offline.
- **Ids** - generated by the app as UUIDs, identical locally and in the cloud,
  which is what makes the upsert collision-free across terminals.

## Backups

Settings, Sync & backup, "Back up local database" runs
`BACKUP DATABASE ... TO DISK` against the local instance and writes a `.bak`
file wherever you choose. The existing "Download SQL backup" button still
exports a re-runnable script of the current in-app state.
