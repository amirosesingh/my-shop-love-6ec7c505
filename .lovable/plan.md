# Part 2, remaining stages: core/api, core/types, platforms/web, capability-driven branches

Continues the approved split. No database, RLS or data changes; `supabase/` stays byte-identical.
`src/routes/` remains the generated TanStack tree (approved decision 1) — only what the route
files import moves.

## Stage A — `src/core/api`

Move the shared data-access layer out of `src/lib` and `src/integrations`:

- `pos-db.ts`, `db-query.ts`, `db-router.ts`, `sync-relay.ts`, `health-relay.ts`,
  `pos-relay.server.ts`, `relay-claims.server.ts`, `relay-policy.server.ts`
- `src/integrations/supabase/*` stays where it is. Those files are integration-managed and
  regenerated by the platform; moving them would break regeneration. `core/api` re-exports the
  client so platform code imports `@/core/api/supabase` rather than the generated path directly.

Imports across the app are rewritten by codemod, then typecheck + full test suite must pass.

## Stage B — `src/core/types`

Move `pos-types.ts`, `payment-types.ts`, `feature-schema.ts` into `src/core/types` and repoint
every importer (`pos-types` alone has a large fan-out, so this is its own stage with its own
verification run).

## Stage C — `src/platforms/web`

Move the 84 screen components in `src/components/pos` (and `src/components/mobile`,
`src/components/database`, `src/components/admin`, `src/components/auth`) into
`src/platforms/web/components/...`, keeping `src/components/ui` where it is — shadcn primitives
are shared UI, not platform screens. Route files under `src/routes/` stay put and import from the
new location, so the router plugin, the build output directory and the Cloudflare deploy are
untouched.

Screens that are genuinely phone-only (`NativeBoot`, `OfflineGate`, `AndroidUpdateBanner`,
`MobileStatusSheet`) go to `src/platforms/mobile/components`, and Windows-only ones
(`WindowControls`, `DbConnectionModal`, `DriverInstallPanel`, `SqlAdminBadge`,
`LocalDatabaseSettings`) to `src/platforms/windows/components`.

## Stage D — capability interfaces instead of platform branches

Nine files still branch internally on the shell: `secure-cloud-config.ts`, `emergency-pin.ts`,
`receipt-printer.ts`, `bill-number.ts`, `backend-config.ts`, `server-origin.ts`, `live-mode.ts`,
`update-manifest.ts`, `layout-store.ts`.

Each becomes:

```text
src/core/<area>/<name>.ts        the interface + shared logic, no platform check
src/platforms/mobile/<name>.ts   Capacitor / Keystore implementation
src/platforms/windows/<name>.ts  Electron / safeStorage implementation
src/platforms/web/<name>.ts      browser fallback (usually a no-op)
```

Selection happens once, in a small resolver that reads `currentPlatform()`, so no component or
shared module calls `isElectron()` / `isNative()` again. Components that today branch for UI
(`AppShell`, `RecoveryHub`, `AppUpdateSettings`, `ConnectionCheck`, `ScanBar`) switch to
`hasFeature("localDb")`, `hasFeature("hardwarePrinting")`, `hasFeature("appUpdates")` and so on
from `platform-config/features.ts`.

`platform.ts` keeps `isElectron()` / `isNative()` as the only detection primitives; a test asserts
they are imported nowhere except `platform-config` and the platform folders.

## Behaviour

None. Every stage is a move plus an import rewrite, or a branch replaced by the same branch read
from one table. Checkout, shift, printing and sign-in paths keep their current behaviour, and the
existing suite is the guard.

## Verification per stage

- `tsgo --noEmit` clean
- full `vitest` run green (324 tests today)
- app serves 200 and the preview renders
- `supabase/` diff empty
- boundary tests extended: no platform-detection import outside allowed folders, no cross-platform
  import, mobile/web never reach `core/local-db`

Version bumped with `node scripts/bump-version.cjs` at the end.

## Risk note

Stage C is the largest single rewrite (84+ files, hundreds of import sites). It is done as one
mechanical codemod with a full verification run immediately after, and is the stage to check
carefully in the Cloudflare preview before merging.
