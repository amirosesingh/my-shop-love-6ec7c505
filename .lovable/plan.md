# Schema v2, Local DB Hardening, and Version 1.3.0

## What this delivers

Two authoritative SQL files that describe the system as it actually runs today (not a renamed rewrite), the safe half of that schema applied to the live cloud database, a hardened Electron local database, and a written flaw report.

## Audit findings (verified)

- The live cloud database uses `members` (not `customers`), `bookings` (racket model, tension, liability, charges all live here — there is no `service_jobs` table), one flat `product_categories` list with a `kind` column, and `uom_units`. The v2 files will use these real names.
- Multi-barcode support is stored as `products.barcode_aliases` (array) and `products.barcode_variants` (JSON) — there is no `product_barcodes` table, so barcode lookups cannot use an index today.
- There is no financial ledger table: `booking_payments` covers bookings only; sale tenders live in `sales.payments` (JSON). Nothing tracks partial settlements across both.
- Inventory audit is split across `stock_adjustments`, `activity_events`, and `audit_logs`; there is no unified item activity view.
- Settings live in a single-row `pos_settings` table plus `settings_overrides`, not a key/value `system_settings`.
- The Electron local database (`local_pos_database.db`) is a generic 4-table store (`mirror`, `outbox`, `sync_audit`, `kv`) with **no PRAGMA statements at all** — no foreign keys, no WAL, no synchronous setting — and falls back to a plain JSON file when `node:sqlite` is unavailable.
- Version is `1.2.108` in `package.json` and `src/version.ts` (generated by `scripts/bump-version.cjs`).

## Deliverables

### 1. `supabase/sql/online_schema_v2.sql`

A single consolidated, idempotent PostgreSQL file that documents and hardens the real schema:

- Full `CREATE TABLE IF NOT EXISTS` definitions for every live table, UUID primary keys with `gen_random_uuid()`.
- Explicit foreign key actions: `ON DELETE CASCADE` for child rows (`sale_items`, `booking_payments`, `purchase_order_items`, `stock_transfer_items`), `ON DELETE RESTRICT` for referenced masters (`products`, `members`, `suppliers`, `stores`).
- Performance indexes on `products(barcode)`, `products(sku)`, `members(phone)`, `bookings(ref)`, `bookings(job_status)`, `sales(bill_number)`, `sales(created_at)`, `activity_events(created_at)`, plus store-scoped composites.
- GRANTs and RLS policies restated for every table, matching the existing role model (`authenticated`, `service_role`, store-scoped helpers).
- New tables:
  - `product_barcodes` — indexed multi-barcode rows, backfilled from `barcode_aliases`/`barcode_variants`.
  - `payment_transactions` — unified ledger of partial payments and settlements across sales and bookings.
  - `item_activity_logs` — one audit trail for every inventory movement (sale, receive, transfer, adjustment).
  - `offline_sync_audit_log` — push/pull direction, status, record counts, error text, timestamps.

### 2. `electron/db/offline_sqlite_v2.sql`

SQLite migration for the local Electron database:

- Leading pragmas: `foreign_keys = ON`, `journal_mode = WAL`, `synchronous = NORMAL`.
- All UUIDs as `TEXT`, timestamps as ISO `TEXT`, so rows round-trip to Postgres unchanged.
- Keeps `mirror` and `kv`, and adds real mirrored tables for the hot entities (`products`, `product_barcodes`, `members`, `sales`, `sale_items`, `bookings`, `booking_payments`, `stock_adjustments`, `shifts`) so offline reads stop scanning JSON blobs.
- `offline_sync_queue` with exactly `id`, `table_name`, `record_id`, `action_type`, `payload_json`, `status`, `error_message`, `created_at`, plus an index on `(status, created_at)`.
- `electron/db/sqlite.cjs` gains a small runner that executes this file on init (pragmas included) and keeps the existing `outbox` working by mapping it onto `offline_sync_queue`.

### 3. Apply the safe parts to the live database

One migration containing only non-destructive work: the four new tables with GRANTs + RLS, the new indexes, and FK action tightening where it does not drop data. No table renames, no drops, no column removals — the running app keeps working.

### 4. Version bump to 1.3.0

Run the existing bump script so `package.json`, `src/version.ts`, Electron main, and the Android/manifest references all move to `1.3.0` together. The header build chip and the Settings → Updates page read `APP_VERSION`, so both update automatically; verify both render `1.3.0`.

### 5. Flaw and logic-gap report

Written into `docs/architecture-audit-v2.md` and summarised in chat: critical flaws (missing pragmas and foreign keys locally, JSON-file fallback that silently loses transactional guarantees, unindexed barcode lookups, no single payment ledger), missing logic (negative stock handling, concurrent offline edits with no version/vector column, void/refund reversal not mirrored into inventory audit, sync retries without backoff caps), and ordered recommended fixes.

## Notes

- Nothing in this plan renames existing tables, so no frontend code changes are required for the schema work; the new tables are additive and will be wired into the app in a follow-up if you want them used immediately.
