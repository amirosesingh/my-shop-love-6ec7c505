# Auto version bumps, automatic releases, Android APK, and the missing drawer table

## 1. Version number goes up on every change

- The app version (`1.0.0`) becomes the single source of truth shown in Software Updates and baked into the Windows installer.
- A small script bumps the patch digit (`1.0.0` -> `1.0.1`) and is wired into the normal build/release flow, so shipping a fix always raises the number.
- The version is also written into a tiny generated file the app reads, so the Updates page, the recovery window and the desktop title all show the same number without a manual edit.

## 2. Releases deploy automatically

Today the Cloudflare R2 workflow only runs on a `v*` tag or a manual click.

- The workflow runs automatically on every push to the main branch: bump patch, build the Windows installer, upload the `.exe` + `latest.yml` + blockmap to the R2 update folder, and push a matching tag/release.
- Concurrency guard so two pushes in a row do not upload half-finished builds over each other.
- Tag pushes and the manual button keep working exactly as they do now.

## 3. Android APK with Capacitor

- Add Capacitor (core, CLI, Android platform) with app id and name matching the POS branding.
- The mobile build points at the hosted app URL so the phone gets the same POS without duplicating the server-side logic; desktop and web builds are untouched.
- A GitHub workflow builds a debug/unsigned `.apk` artifact on demand; signing keys can be added later as repository secrets for a release build.
- Desktop-only features (silent printing, drawer kick, local SQL Server) stay behind the existing "is this Electron" checks, so on Android they simply do not appear.
- `docs/` gets a short "Build the Android APK" page.

## 4. The missing drawer table

The register talks to your own database project, and the no-sale drawer log table was never created there, which is why opening the drawer reports `public.drawer_events` missing from the schema cache.

- A new `supabase/schema14.sql` you run once on that database creates the drawer event log (store, terminal, shift, staff, role, reason, note, approver, timestamp) with staff-only read/append access.
- The same script also adds the other pieces that were introduced after your last schema run — the split-payment breakdown on sales and the review-threshold settings columns — written so it is safe to re-run.
- Until the script is run the drawer still opens; the failed cloud write is already kept locally and retried, and the error message will say plainly that the log table is missing.

## Technical notes

- `scripts/bump-version.cjs` bumps `package.json` patch; called from `scripts/desktop-release.cjs` and the CI workflow, committing the bump back with `[skip ci]`.
- `.github/workflows/node.js.yml`: add `push: branches: [main]`, a bump+commit+tag step, and `concurrency: desktop-release`.
- `.github/workflows/android-apk.yml`: JDK 21 + Android SDK, `npx cap sync android`, `gradlew assembleDebug`, upload APK artifact.
- `capacitor.config.ts` with `server.url` pointing at the published site; `android/` generated by `cap add android`.
- `supabase/schema14.sql`: `CREATE TABLE IF NOT EXISTS public.drawer_events` + GRANTs + RLS + `is_staff` policies, `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` for `sales.payments` and `pos_settings.review_*`.
