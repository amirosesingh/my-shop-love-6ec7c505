# Finish the audit follow-through

The Phase 2 work (P0–P5) is now built. Reviewing what shipped against the sync
lists in the till code turned up four loose ends left over from that work.

## What is left

1. **Purchasing history cannot be recovered.** Purchase orders and their lines
   are sent up to head office and are marked as "needed after a rebuild", but
   they are not in the till's restore list. A replaced terminal comes back
   without any purchase history. Stock count drafts have the same gap.
2. **Two tables are labelled wrongly in the new coverage screen.** Membership
   tiers are marked "lives centrally only" even though the till downloads them,
   so the new screen would report a problem that isn't real.
3. **The coverage document is written by hand.** The audit file says it is
   generated by a script, but that script was never created, so the document is
   already out of date and will drift again.
4. **The Phase 2 plan document still says nothing has been built.** It should
   record what shipped, so the next person reading it isn't misled.

## What will change

- Add purchase orders, purchase order lines and stock count drafts to the
  branch-scoped, date-windowed restore, in the right order so a parent always
  arrives before its lines.
- Correct the declared intent for membership tiers (and re-check the other
  reference tables) so the coverage screen only reports real gaps.
- Add a small script that regenerates the coverage document from the feature
  list and the till's own sync lists, and regenerate the document with it.
- Mark the delivered items in the Phase 2 plan with what shipped.
- Bump the app version.

## Technical notes

- `electron/db/repo.cjs`: extend `RESTORE_TABLES` with
  `{ table: "purchase_orders", storeColumns: ["store_id"], dateColumn: "created_at" }`,
  `{ table: "purchase_order_items", parent: { table: "purchase_orders", column: "purchase_order_id" } }`
  (column name confirmed against the schema before writing) and
  `stock_count_drafts` scoped by store. No worker changes needed — `restore()`
  already iterates this list.
- `src/lib/sync-coverage.ts`: change `membership_tiers` to `pull`; verify each
  reference table's declared direction against `CATALOGUE_TABLES` /
  `SCOPED_PULL_TABLES`.
- `scripts/sync-coverage.cjs`: read `PUSH_TABLES`, `CATALOGUE_TABLES`,
  `SCOPED_PULL_TABLES` and `RESTORE_TABLES` from `electron/db/repo.cjs`, build
  the matrix with the same rules as `buildCoverage`, and write
  `docs/audit/sync-coverage.md`. Node-only, no bundler needed.
- `node scripts/bump-version.cjs` at the end.
